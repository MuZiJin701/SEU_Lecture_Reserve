# 邮件通知需求

2026-10-18 确认：保留独立脚本，每位用户可选地配置自己的发件邮箱，重要通知与每日进度汇报发送到其指定收件地址。无需维护统一发信后台。

## 配置与通知

- 邮件全部缺省或为空时关闭，不影响预约。Gmail 只需邮箱和应用专用密码；收件地址可选，默认发给自己。其他发件服务沿用现有显式 SMTP 配置。
- 双语 README 在首次运行前提供 Gmail 应用专用密码的完整获取和填写步骤，覆盖开启两步验证、创建 16 字符密码、去掉分组空格、填写 `.env` 及测试邮件；入口不可用和密码撤销的排错见使用指南。
- 重要通知和错误即时发送，包括预约成功、目标完成、人工认证、预约结果待确认、连续三轮查询或处理失败，以及可捕获的异常退出。
- 连续失败告警后，同一进程首次完整恢复当前模式的查询／处理时通知一次；部分读取或仅登录成功不算恢复。待确认模式的查询恢复不代表预约成功。短暂失败、持续正常运行及重启不补发恢复通知，发送失败不重试。
- 运行期间，每天北京时间 20:00 汇报已选听和待参加数量、必需类别缺口、最近查询结果及待处理问题。
- 不因发信失败改变预约结果或触发重复预约。
- 邮件提供中文事件说明和处理建议，不发送学校凭据、讲座详情、完整个人活动记录或原始异常。
- 测试邮件和运行通知共享固定错误分类，覆盖 DNS、连接、TLS、超时、认证、收发件拒绝及其他异常；日志只输出安全分类，不输出异常原文、地址或 SMTP 响应内容。状态保存 `last_mail_error` 并跨重启保留，旧失败记录缺分类时为 `unknown`，新尝试开始或成功时为 `none`。

## 每日汇报边界

- 只在已启用邮件的运行实例内安排，无需系统定时任务或后台服务。页面操作期间可能延迟到安全等待点发送；业务退避不会因发信而提前结束。
- 当天 20:00 后启动，在首次等待时尝试当天汇报；不补发之前日期。只读检查、停止运行及目标完成退出后不继续汇报。
- 同一状态目录每天最多尝试一次，发送前保存时间，重启不重复。发信失败只记本地事件，不自动重发，SMTP 接受不保证送达。
- 汇报使用最近一次成功核对的数量并标明时间；数据未知时明确显示未知。待确认结果、连续失败及最近查询情况单独说明。

回归检查覆盖自定义收件人、中文内容、北京时间边界、跨日与重启去重、退避期间汇报、待确认保护、发信失败、关闭邮件、只读检查、安全错误分类及连续失败后的恢复通知。

Gmail 发信有额度与反滥用限制，应用专用密码仅由用户自己保管。参见 [Google 应用专用密码](https://support.google.com/accounts/answer/185833)和 [Gmail 发送限制](https://support.google.com/mail/answer/22839)。
