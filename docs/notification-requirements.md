# 邮件通知需求

2026-10-18 确认：保留独立脚本，每位用户可选地配置自己的发件邮箱，重要通知与每日进度汇报发送到其指定收件地址。无需维护统一发信后台。

## 配置与通知

- 邮件全部缺省或为空时关闭，不影响预约。QQ、163、126、Gmail 只需完整邮箱和授权码／应用专用密码，按域名自动选择主机；收件地址可选，默认发给自己。显式主机配置优先，其他域名须填写主机，默认端口 465。
- `.env.example` 注释解释每个邮件字段、默认值及覆盖规则。双语 README 在首次运行前提供 QQ／网易开启 SMTP、生成授权码及 Gmail 两步验证、创建 16 字符应用专用密码、去掉分组空格、填写 `.env` 和测试邮件的教程；入口不可用和密码撤销的排错见使用指南。
- 重要通知和错误即时发送，包括预约成功、目标完成、人工认证、预约结果待确认、连续三轮查询或处理失败，以及可捕获的异常退出。
- 认证受阻、预约待确认和连续查询失败的告警在发送前持久化，同一未解决问题跨重启只尝试一次，解决后清除。连续失败告警后首次完整恢复当前模式的查询／处理时通知一次，可接续重启前保存的告警；部分读取或仅登录成功不算恢复。待确认模式的查询恢复不代表预约成功。短暂失败、持续正常运行及没有告警记录时不发恢复通知，发送失败不重试。查询失败告警之间至少间隔十五分钟以抑制反复故障；冷却期内的新故障持续到期后再告警，不改变学校查询和退避节奏。
- 运行期间，每天北京时间 20:00 汇报已选听和待参加数量、必需类别缺口、最近查询结果及待处理问题。
- 不因发信失败改变预约结果或触发重复预约。
- 邮件提供中文事件说明、处理建议、最近核对的整体进度、安全错误码、连续失败次数和下次检查计划；未知数据和计划明确标注。预约成功通知使用本轮核对进度。不发送学校凭据、讲座详情、完整个人活动记录或原始异常。
- 测试邮件和运行通知共享固定错误分类，覆盖 DNS、连接、TLS、超时、认证、收发件拒绝及其他异常；日志只输出安全分类，不输出异常原文、地址或 SMTP 响应内容。状态保存 `last_mail_error` 并跨重启保留，旧失败记录缺分类时为 `unknown`，新尝试开始或成功时为 `none`。

- 状态保存最近运行通知的 `last_mail_event` 和 `last_mail_duration_seconds`，覆盖成功、失败及重启；未完成尝试和旧记录的未知耗时不冒充零秒。结束尝试后仅在本地日志记录事件和耗时。
- 保持同步 SMTP 及不自动重发；先测量发送耗时，再以是否影响扫描决定是否增加线程。网络操作超时不作为整封邮件的总耗时保证，不增加后台队列或新依赖。

## 每日汇报边界

- 只在已启用邮件的运行实例内安排，无需系统定时任务或后台服务。页面操作期间可能延迟到安全等待点发送；业务退避不会因发信而提前结束。
- 当天 20:00 后启动，在首次等待时尝试当天汇报；不补发之前日期。只读检查、停止运行及目标完成退出后不继续汇报。
- 同一状态目录每天最多尝试一次，发送前保存时间，重启不重复。发信失败只记本地事件，不自动重发，SMTP 接受不保证送达。
- 汇报使用最近一次成功核对的数量并标明时间；数据未知时明确显示未知。待确认结果、连续失败及最近查询情况单独说明。

回归检查覆盖自定义收件人、中文内容、北京时间边界、跨日与重启去重、退避期间汇报、待确认保护、发信失败、关闭邮件、只读检查、安全错误分类、跨重启的告警与恢复、十五分钟告警间隔、成功通知的新进度和发送耗时保留。

Gmail 发信有额度与反滥用限制，应用专用密码仅由用户自己保管。参见 [Google 应用专用密码](https://support.google.com/accounts/answer/185833)和 [Gmail 发送限制](https://support.google.com/mail/answer/22839)。

## SMTP 多邮箱方案确认（2026-10-19）

用户认为 Gmail API 的项目注册及 OAuth 配置不方便面向普通用户，要求重新考虑 SMTP，并提供常见发件邮箱供用户自行选择。用户对原 SMTP 方案报告了以下网络对照；这些是用户实测反馈，本轮未另行复测、未读取私有日志，具体连接失败阶段与收件箱证据仍未复核：

| 网络 | Clash 状态 | 用户报告的发信结果 |
| --- | --- | --- |
| 校园网 | 关闭 | 失败 |
| 校园网 | 开启 | 失败 |
| 手机热点 | 关闭 | 成功 |
| 手机热点 | 开启 | 失败 |

若四组使用相同账号与参数，热点直连成功说明原账号、凭据和 SMTP 实现至少在当次存在可用路径；热点启用 Clash 后失败表明网络路径或运行状态变化与失败相关。尚不能确定具体拦截位置，也不能据此断定所有代理、校园网中的全部 SMTP 服务或其他发件邮箱都不可用。服务商配置便利性与 SMTP 网络可达性需要分别验收。

调整前已有显式 `SMTP_HOST`、`SMTP_PORT`、发件账号及单个收件地址，默认自己给自己发信，仅 Gmail 自动补全主机。继续使用校验证书的 `SMTP_SSL`，默认 465，不支持 STARTTLS。发件服务与收件服务可不同，例如 QQ 发件、Gmail 收信。

首轮已确认：支持范围为 QQ、163、126、Gmail 加自定义 SMTP；在 `.env.example` 注释中说明各字段应如何填写，并在双语 README 提供填写及授权码获取教程；每次配置一个发件账号，由用户手动选择和切换，不增加多账号自动轮换或系统代理管理。

最终选择 A：按 `SMTP_USERNAME` 域名自动补全 SMTP 主机，保留显式配置优先。`qq.com`、`163.com`、`126.com`、`gmail.com`（不区分大小写）分别对应 `smtp.qq.com`、`smtp.163.com`、`smtp.126.com`、`smtp.gmail.com`，不推断其他域名或别名。`.env.example` 中每个邮件字段均有注释，模板默认关闭邮件；移除已放弃的网页登录实验字段，实验结果留在历史文档。不新增邮箱选择字段、OAuth、网页登录或自动切换网络逻辑，不改变既有通知、去重和失败处理规则。

服务商资料核查支持这批候选沿用 SSL 465 和授权码／应用专用密码。QQ 的官方帮助页未能取得正文，使用腾讯官方产品文档交叉核对；网易资料中的 587 未可靠区分 TLS 模式，因此不将其作为首期配置。Outlook.com 官方设置使用 587 STARTTLS 与 OAuth2，暂不建议作为当前实现的简化预设。参考：[腾讯 SMTP 示例](https://cloud.tencent.com/document/api/876/129350)、[网易客户端设置](https://help.mail.126.com/faqDetail.do?code=d7a5dc8471cd0c0e8b4b8f4f8e49998b374173cfe9171305fa1ce630d7f67ac25c12dcb3d46222b6)、[Gmail SMTP 协议](https://developers.google.com/workspace/gmail/imap/imap-smtp)、[Outlook.com 设置](https://support.microsoft.com/en-us/outlook/pop-imap-and-smtp-settings-for-outlook-com)。这些资料不证明对应服务在用户校园网可达。
