# 高峰预约、待确认恢复与邮件需求

以下策略已经用户确认并落实到代码。运行入口与配置见[中文指南](usage.md)／[English guide](usage.en.md)，当前规格见[浏览器规格](browser-upgrade-requirements.md)，风险取舍见[自动恢复决策](adr/0002-automatic-unconfirmed-recovery.md)。

## 已确认规则

- 以高峰抢约为优先：预约开放前三十秒至后十分钟（不晚于预约截止），即使全满也保持一秒整轮目标周期，不并发，明确限流遵守等待。
- 待确认完全自动处理。连续两次新的个人记录查询通过页面和完整业务校验、且均不存在原活动有效预约，两次之间等待一秒，即自动解除并重新扫描，允许再试原活动。不提供人工恢复入口、永久屏蔽或未知预约占位。
- 任何一次核实原预约有效就确认成功；查询错误、认证、限流或异常数据打断核对计数，不能当作未预约。重启和旧待确认状态均重新开始两次核对，不依赖缓存或旧计数。
- 自动解除不表示原提交已证实失败。用户接受学校记录延迟时重复提交、潜在时间冲突及临时超出目标的风险；不自动取消学校预约。
- 高峰期提交前的取图异常最多尝试四次，失败间额外等待一秒，耗尽仅该活动冷却十秒，其他候选继续处理。非高峰取图错误仍普通退避；OCR 无效／明确验证码错误的四次上限与五分钟冷却不变。
- 导航、页面就绪、个人记录导航和预检错误在高峰期短重试，包含待确认阶段；短重试不抬高普通退避的起点，完整连续故障次数仍可诊断。
- 邮件仅保留无法继续的认证、异常退出、连续五分钟未完成有效查询。同一未解决事件发送前持久化标记，跨重启只尝试一次；发信失败不自动重发，恢复对应功能后才能开启下一次告警。
- 普通问题、短暂待确认、预约成功、目标完成、查询恢复和每日报告不发邮件；相关结果仍保留本地。20:00 后启动也不补日报，旧邮件历史继续兼容。

## 验证与运行边界

离线回归覆盖自动解除、迟到预约阻止重提、核对错误重置、重启重新核对、验证码取图的短重试和活动冷却，以及重大邮件的时间阈值和跨重启去重。没有新增依赖或配置项，现有状态目录继续复用。

[Playwright 自动等待](https://playwright.dev/python/docs/actionability)与页面／结果等待上限仍适用；一秒是调度目标，学校超载时整轮可能更慢，模板的元素／结果等待仍为十五秒。本次未操作生产服务、真实预约、取消或发信；不能由离线结果推断真实高峰成功率。
