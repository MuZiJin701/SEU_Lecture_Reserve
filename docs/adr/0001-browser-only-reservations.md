# 全程由 Playwright 操作浏览器，保持两个项目独立

2026-10-18，用户明确保留独立的 HTTPS 客户端，并要求本项目采用全程浏览器操作。后续确认覆盖早期按平台自动选择的方案：所有平台普通启动默认有头，用户通过 `--headless` 自行选择无头。登录、切换列表、打开预约弹窗、填写验证码、提交及结果核对均通过 Playwright 操作页面；不采用“浏览器登录后另建接口客户端”的混合方案，以保留可见的页面操作过程。

本项目迁入 HTTPS 项目已有的目标统计、任务状态和可选邮件逻辑，源项目保持不变，两仓库运行时互不依赖。页面没有直接展示稳定 ID 和全部状态文字，因此只读访问当前 Vue 页面绑定的数据，再以稳定 ID 定位卡片；不调用 Vue 业务方法、不注入 fetch／XHR、不使用 Playwright 请求上下文执行业务。代价是继续依赖学校页面与 Vue 结构，页面改版或记录完整性无法确认时须暂停新增预约，不能退回标题猜测或默认无冲突。

不开发短信交互或远程桌面；认证无法完成时保留任务、停止业务并按邮件配置通知。无头模式和邮件不代替学校认证，也不保证长期无人值守。

个人预约、打卡和目标进度以每次正常启动后登录网站取得的记录为准，包括本地曾标记完成时。本地检查点仅辅助本机失败恢复，不开发跨机器接续，也不要求迁移状态目录后才能启动。实现依据见[浏览器改造规格](../browser-upgrade-requirements.md)，验证边界见[使用指南](../usage.md#开发与验收)。
