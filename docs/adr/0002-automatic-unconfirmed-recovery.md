# 两次有效核对后自动解除待确认，优先争取高峰名额

学校超载时提交结果可能不明，原来的无限核对会阻断后续放号。用户明确接受重复提交、潜在冲突和临时超出目标的风险，决定在连续两次新的个人记录查询通过页面及完整业务校验且均未找到原预约时自动解除待确认，两次查询间隔一秒，重新扫描并允许重试原活动；重启重新计数，异常查询不能作为未找到的证据，成功仍须按活动 ID 核实。

此决定取代原规格中“未核实结果则无限期禁止新增”的约束，不引入人工恢复入口或长期屏蔽；完整数据校验、单实例与浏览器交互边界仍遵循[原决策](0001-browser-only-reservations.md)。它优先保障自动继续的机会，放弃对未知提交的至多一次保证；两次未找到不是服务端未受理的证明，不依赖尚未验证的学校接口幂等性，也不自动取消可能迟到的预约。通用的保守重试原则见 [RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)，本项目的主动取舍与边界见[已确认需求](../peak-recovery-requirements.md)。
