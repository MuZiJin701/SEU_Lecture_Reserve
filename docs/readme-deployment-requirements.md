# README 与服务器部署需求

2026-10-18 用户已确认以下范围与命令呈现方案。

## 已确认

- 双语 README 按实际使用顺序编排：安装项目和浏览器 → 填写学校账号、预约偏好及可选邮件 → 验证登录和可选邮件 → 选择本地运行或服务器后台运行 → 查看日志、停止与恢复。
- 所有配置集中在首次运行之前。邮件仍由每位用户可选地配置自己的发件账号，默认发给自己，每日汇报保持北京时间 20:00。
- 服务器主路径面向 Ubuntu 24.04 LTS，用户拥有 sudo 权限；保留 Windows 本地运行步骤。
- 服务器关闭终端／SSH 断开后继续运行；服务器重启或程序退出后由用户手动启动。人工认证受阻和目标完成时沿用现有停止行为。
- README 应能独立指导首次安装、配置、验证和后台运行，详细配置及验证记录放使用指南。
- 使用常见命令，尽量减少参数，保留必要的无头运行、只读检查与测试邮件入口。

## 命令呈现方案

- 运行命令使用 `uv run main.py`；服务器使用 `uv run main.py --headless`，避免每条命令重复锁文件参数。
- 浏览器安装使用 `uv run playwright install chromium`，Ubuntu 安装时按需增加 `--with-deps` 准备系统运行库。
- 后台运行采用 `nohup`、输入输出重定向和 `&`；启动步骤同时创建日志目录并保存 PID。随后给出查看状态和日志、核对进程后停止、用原命令重新启动的完整步骤。
- 保持现有命令入口，安装缺失提示与文档中的命令保持一致。简化安装命令会下载 Playwright 默认附带的无头专用包；运行仍使用完整 Chromium。

## 验收边界

检查中英说明一致、步骤先后合理、路径与文件可由前序步骤产生，所有内部链接有效。命令涉及的真实学校访问和真实发信须单独授权验收。后台启动应在目标机器实际断开 SSH 后确认进程和成功查询仍在继续，不能仅凭启动命令返回成功宣称验收通过。

使用指南与 README 的引用必须一致，后台步骤须先创建日志目录、生成 PID，再使用这些文件查看和停止进程。
