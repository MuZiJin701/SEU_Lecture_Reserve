本页保留当前业务规则、技术边界和验证状态。已完成的需求讨论、网络采样和实验过程通过 Git 历史查阅；不作为运行步骤。

## 选听目标与筛选

- 本程序目标是实际参加至少八场系列讲座或 SEU 咖啡间沙龙，法律、艺术、心理健康各至少一场。只计学校已打卡、未违约、未取消且按冲突规则选入本地统计的记录；测试及购票公告不自动预约、不计数。学校最终认定以学校规则为准。
- 已选听和有效待参加预约共同占用目标缺口；计划覆盖后等待，实际选听达标才完成。取消或违约后补足；已结束但打卡／违约不明确时暂停新增。必需类别优先并预留缺口，已有八场仍缺类别时只补必要类别。历史统计不受候选筛选限制。
- 候选同时满足配置类别、完整标题、校区、线上线下和时间条件；指定标题不绕过筛选。未配置线下校区时不约线下。授课方式只认标题开头明确的【线上】／【线下】标记。
- 校区只从学校 `JZDD` 提取开头至第一个“校区”的文字，无匹配则保留完整地点；与白名单精确匹配，不归一空格或别名，不根据城市／场馆猜测。线上候选不受校区白名单限制，但仍校验必要字段。测试／购票公告先排除，不据其试约成功推断校区归属，示例见[校区识别与指定活动测试](usage.md#校区识别与指定活动测试)。
- 非空有效类别明确不在配置中时先排除，允许该记录缺少其他候选字段。其他候选逐条校验标题、类别、地点、稳定 ID、活动时间及已提供的预约时间，包括不可预约记录；失败时标记 `invalid_activity_data` 并跳过，不阻断其他候选。具体 `validation_error` 保留在私有状态与筛选变化诊断中，事件日志和合并邮件仅提示通用错误码。只读检查输出警告、继续读取，不发邮件或写状态。个人记录完整校验，未知或矛盾数据暂停新增，不当作空历史或无冲突。
- 活动起止时间允许相同，候选与个人历史统一按一个时间点处理，不推断持续时长；结束早于开始、缺失或无法解析仍失败。相同时间点仍参与端点相接和包含关系的冲突判断，真实时长超出该点的冲突无法保证识别；未打卡且到达记录结束时间仍等待结果核实。预约开放与截止时间仍严格要求截止晚于开放。
- 身份和去重依据是活动 ID。新增预约与全部有效预约检查时间冲突，首尾相接也算冲突。已有重叠逐次按已打卡、当前缺少类别、结束较早、活动 ID 排序选择本地计数，不保证全局最多场次；未计数的有效预约仍阻止冲突，不自动取消学校记录。
- 候选先补必需类别，其余按配置类别顺序、线上优先、开始较早排序。首次预检复用刚完成扫描的页面，重新校验当前活动 ID、按钮和页面完整性；验证码重试与异常恢复仍刷新。正常每轮完成后等待十秒；围绕页面提供的预约开始时间，前三十秒至后十分钟（不晚于预约截止）改为一秒整轮目标周期，超时立即继续，不并发；缺时间不按整点猜测；已登录且未提交时，导航失败、页面未就绪、个人记录导航失败及预检失败额外等待一秒重试，窗口结束恢复普通退避。启动可使用已记录的有效开放时间调度，新增仍完整读取和校验学校数据；限流、认证、数据异常、待确认查询及已持久化的退避期限不被缩短。验证码初次尝试后最多再取图三次，仍失败则该场冷却五分钟；明确已满或不可预约可换下一场，超时或未知结果不当作验证码错误。

普通扫描每轮重新读取个人记录。抢约窗口内，扫描开始时允许复用不足十秒（或更短的配置扫描间隔）的内存个人记录，活动列表每轮刷新；若发现候选且本轮未更新个人记录，先重新查询个人记录、进度及活动列表，再筛选和预检。已有预约、冲突和异常历史仍阻止提交。缓存不落盘，启动、异常恢复和待确认核对均读取新记录；进度时间保留真实查询时间。查询个人记录时可复用上一轮完整活动页面以省去一次整页刷新。

正常启动在取得任务锁、等待已有退避后于登录前初始化一次 OCR，后续识别复用实例；源码导入和只读／状态／邮件检查不加载模型。继续使用锁定的 ddddocr 1.4.11 与 Playwright 1.64.0，已核对安装源码的构造加载及刷新行为；[ddddocr 官方说明](https://github.com/sml2h3/ddddocr#常见问题)建议只初始化一次，[Playwright reload 文档](https://playwright.dev/python/docs/api/class-page#page-reload)明确刷新会重新导航页面。十秒复用期限是本项目的调度取舍，不代表允许基于缓存直接提交。

筛选变化、预检跳过、每次提交的安全结果分类及确认成功追加写入私有 `diagnostics.jsonl`，保留活动 ID 和耗时，`ocr_ready` 记录模型预加载、`scan_timing.history_reused` 标记个人记录复用；未知结果另保留是否观察到未识别提示、等待超时及浏览器观察到的提交 HTTP 状态，不将 HTTP 200 或未知提示当作成功或明确失败。不保存验证码或原始响应，不将详情写入事件日志和邮件。明确授权的测试预约验证后必须取消并核对取消结果，不取消测试前已有预约，不涉及付款。

## 提交与恢复

- 每次普通启动都先登录学校、读取个人记录并重建进度，即使本地曾标记完成。本地状态只辅助恢复与诊断，不代替学校记录；新机器无需先迁移状态。
- 真实提交前原子保存 `pending` 和活动 ID。页面提示成功后仍核对原 ID；开抢期间的结果不明浏览器错误在额外等待一秒后核对原预约；超时、断线或结果不明时只核对原预约，暂停其他提交并按配置通知。重启保留待确认、冷却与退避，不能删除状态绕过保护。
- 成功通知必须在新查询的个人记录中按原活动 ID 核实有效预约后发送；源码／提示包含“成功”、其他活动已有预约、HTTP 200 或 URL 改变均不作为独立成功依据。跳回登录页按认证失效处理；未核实结果前不重复提交、不预约下一场，一场确认成功后继续补足选听目标。
- 同账号在所有机器和两个项目间只运行一个实例。锁仅覆盖同一状态目录，不提供跨主机锁、状态同步或跨机器提交去重。
- 会话失效可先重登；无法完成认证、明确凭据拒绝或账号受限时保存任务、停止业务并按配置通知。不提供短信发送、输入、远程桌面或认证绕过。
- 页面关闭／浏览器断连记录 `browser_closed`，保留任务、尝试告警后退出；提交中保留 `pending`。页面和网络错误按上述窗口与错误类别选择短重试或普通退避，配置的页面／请求等待上限不变。Ubuntu 后台使用系统级 systemd 临时服务隔离完整进程树，不自动重启或开机自启。

## 浏览器与传输边界

- 与[独立 HTTPS 项目](https://github.com/MuZiJin701/seu-lecture-reserve-http)无运行时依赖。业务交互全程由 Playwright 同步 API 操作页面，共享 Playwright 管理的 Chromium，统一 `channel="chromium"`，排除 `--enable-logging`。不发现系统 Chrome，不使用 ChromeDriver。
- 所有平台默认显示窗口，只有 `--headless` 选择无头；辅助采集入口语义相同，旧模式环境变量不覆盖命令行。
- 页面导航和控件操作触发学校业务；仅只读当前 Vue 绑定数据以取得 ID 和状态，不调用 Vue 业务方法、不注入 fetch／XHR、不另建业务请求客户端。校验加载、全部筛选、卡片数量及已有总量证据；页面 `count` 是未读通知数，不能证明全历史完整。
- 凭据仅在受信学校 HTTPS 页面填写，保留证书校验。遗留学校 HTTP 回调以浏览器本地 307 响应升级为同主机 HTTPS，保留原 service 标识，不发原始 HTTP 请求；其他 HTTP 请求阻断。
- 首次登录先正常 DNS。仅准确主机 `vpn.seu.edu.cn` 的未恢复主框架导航出现 `ERR_NAME_NOT_RESOLVED`、`ERR_CONNECTION_CLOSED`、`ERR_CONNECTION_RESET` 且登录失败时，使用配置的备用 IP 关闭原浏览器并重启一次。成功登录、子资源、其他域名、普通超时、证书或认证错误不回退；业务阶段不切换 IP、不重放提交。
- 备用值仅接受单个 IPv4／IPv6，空值关闭。只映射 VPN 域名，保留域名、TLS 身份及证书校验，不保存登录态、不改系统 DNS 或代理；代理远端解析可能忽略映射。模板地址为 2026-10-16 历史验证值，不保证持续可用。
- 诊断仅输出允许的学校域名与安全错误码；其他域名为 `<unknown>`，不输出完整 URL、凭据、Cookie、票据或原始异常调用日志。两类已确认的深信服本地 HTTPS XHR 探测在同一浏览器合并提示：`127.0.0.1` 的 `54630/54641/54652` 端口拒绝连接，以及 `localhost.sangfor.com.cn` 的 `54631/54642/54653` 端口中止或拒绝连接。其他请求和证书错误保留。
- `.env`、状态、生成样本和登录诊断文件仅留本地，不自动保存认证页面或截图。已有 `image/`、`images/` 是项目素材，保持原状。

## 通知约束

- 邮件可选，每人配置自己的单个发件账号；QQ、163、126、Gmail 按域名补全 SMTP 主机，显式设置优先，默认发给自己。使用校验证书的 `SMTP_SSL`，不提供 STARTTLS、OAuth、网页登录发信、自动账号轮换或网络切换。
- 预约成功、目标完成、认证受阻、待确认结果、连续三轮查询／处理失败和可捕获退出按规则通知。未解决的认证、待确认和查询告警发送前持久化，跨重启去重；查询完整恢复后通知一次，两次查询失败告警至少相隔十五分钟。
- 运行期间每天北京时间 20:00 汇报，同一状态目录每天最多尝试一次；当天晚启动可补当天，停止和完成后不再汇报。未知数据明确标记，发信失败不重发、不改变预约结果，SMTP 接受不保证送达。
- 单次运行问题也可发汇总邮件，同类原因十五分钟内合并并跨重启限频，发信失败不自动重发；开抢期间延后至普通扫描、普通长退避或退出，一秒短重试不触发同步邮件。查询失败、查询恢复及每日报告也避免占用加速扫描和短重试时间。保留最近运行发信的时间、状态、安全错误分类、事件和耗时，兼容旧记录的未知值。只发送整体进度和安全诊断，不发送讲座详情或完整个人记录；同步发送的网络超时不等于整封邮件总时限。操作细节见[邮件配置](usage.md#邮件配置)。
