## Problem Statement

用户希望独立保留 HTTPS 讲座预约项目，同时把浏览器项目改造成可在 Windows 主机或 Linux 服务器上用 uv 启动的 Playwright 预约工具。用户自行决定是否显示浏览器窗口，不希望程序按操作系统替自己选择，也不需要跨机器接续、状态迁移或远程桌面流程。

浏览器项目原先采用成功一场后退出、指定标题可跳过其他筛选等规则，与用户现在确认的八场选听目标和预约保护规则不同。仅增加无头开关不能满足需求，需同时采用 HTTPS 项目已确认的业务规则，但所有学校业务交互仍通过浏览器页面完成。

本文为 2026-10-18（Asia/Shanghai）讨论后的规格。此前提前生成的实现及测试是待审查草稿，不构成本规格已实现或已验收的证据；本文优先于先前关于按系统自动选择模式、要求手动迁移状态目录的讨论与文档。

## Solution

只改造浏览器项目 `SEU_Lecture_Reserve`，不改动独立的 `seu-lecture-reserve-http` 项目，不合并仓库或建立运行时依赖。

用户在任一受支持环境中直接使用 `uv run main.py` 启动，默认有头；使用 `uv run main.py --headless` 选择无头。Windows 和 Linux 采用相同约定，不自动按平台切换，也不需要新增反向开关。

正常启动后通过浏览器登录学校网站，读取讲座、预约及打卡记录，核对选听进度并按完整筛选条件尝试预约。目标为至少已选听八场系列讲座，其中法律、艺术、心理健康各至少一场。已选听和有效待参加预约共同占用缺口；计划覆盖后暂停新增，实际已选听达标才结束。

个人业务记录以学校网站为准，本地任务记录只辅助本机失败恢复和诊断。换一台机器不需要先迁移状态目录才能启动，也不要求程序提供跨机器接续能力。邮件通知可选；认证要求人工介入时保存任务、停止业务，并在已配置邮件时通知后退出。

## User Stories

1. 作为用户，我希望独立保留 HTTPS 项目，以便继续使用原工具而不受浏览器项目改造影响。
2. 作为用户，我希望在准备好环境后直接用 uv 启动浏览器项目，以便保持简单的使用方式。
3. 作为用户，我希望不加模式参数时显示浏览器，以便观察登录和预约操作。
4. 作为用户，我希望加上 `--headless` 后无头运行，以便在没有桌面的服务器上使用。
5. 作为用户，我希望 Windows 和 Linux 都按同样的参数约定运行，以便自己决定模式。
6. 作为用户，我希望模式选择不被操作系统或隐藏的环境配置覆盖，以便启动命令明确表达我的选择。
7. 作为用户，我希望两种模式采用完全相同的业务规则，以便显示窗口与否不影响预约结果。
8. 作为用户，我希望登录、查看列表、填写验证码、提交和核对都由 Playwright 操作页面，以便保留浏览器自动化项目的定位。
9. 作为用户，我希望程序能只读页面已加载的数据，以便取得页面文字未完整展示的活动 ID 和状态。
10. 作为用户，我希望正常启动时先登录网站并核对个人进度，以便学校记录而非本地缓存决定是否需要继续预约。
11. 作为用户，我希望已有的手动预约和其他工具产生的学校记录也参与核对，以便不重复占用目标缺口。
12. 作为用户，我希望在另一台机器上也能直接启动并读取学校记录，以便无需学习状态迁移流程。
13. 作为用户，我希望目标为至少八场已选听系列讲座，以便跟踪已经确认的个人选听要求。
14. 作为用户，我希望法律、艺术、心理健康各至少一场，以便满足必需类别要求。
15. 作为用户，我希望沙龙既不自动预约也不计数，以便统计口径一致。
16. 作为用户，我希望已选听仅计入学校已打卡、未违约且未取消的有效场次，以便不把预约成功当作已经参加。
17. 作为用户，我希望有效待参加预约占用剩余缺口，以便避免提前约入过多场次。
18. 作为用户，我希望计划覆盖后暂停新增并继续核对，以便等待实际参加结果。
19. 作为用户，我希望只有已选听自身达标才完成任务，以便不因预约数量足够而过早结束。
20. 作为用户，我希望取消或学校标记违约后能补足缺口，以便计划变化后仍能继续完成目标。
21. 作为用户，我希望已结束但打卡或违约结果未明确时暂停新增，以便避免重复补约。
22. 作为用户，我希望优先补齐缺少的必需类别并给它们预留名额，以便普通类别不会占满剩余计划。
23. 作为用户，我希望已有记录导致需要超过八场时只补必要类别，以便不预约与目标无关的额外场次。
24. 作为用户，我希望类别、校区、线上线下、标题和时间冲突条件共同生效，以便每一场候选讲座都符合要求。
25. 作为用户，我希望指定标题仍受其他筛选约束，以便不会意外预约不合适或冲突的讲座。
26. 作为用户，我希望未配置线下校区时不约线下，以便默认行为明确可控。
27. 作为用户，我希望历史目标统计不受候选筛选排除，以便不会漏算已经参加的讲座。
28. 作为用户，我希望按活动 ID 识别和去重，以便同名讲座不会混淆。
29. 作为用户，我希望与全部有效预约检查冲突，首尾相接也视为冲突，以便避免重叠安排。
30. 作为用户，我希望候选时间解析失败时跳过、已有记录不完整或矛盾时暂停新增，以便未知数据不会被当作无冲突。
31. 作为用户，我希望已有重叠记录只影响本地计数选择，以便程序不会擅自取消学校预约或标记违约。
32. 作为用户，我希望未计入本地统计的有效预约仍参与冲突检查，以便不会忽略实际占用的时间。
33. 作为用户，我希望候选有稳定的类别、线上和时间优先级，以便选择过程可解释。
34. 作为用户，我希望某场明确失败后能考虑下一候选，以便不会一直被同一场阻塞。
35. 作为用户，我希望验证码识别失败或明确错误时重试有界并对该场冷却，以便避免无限重复操作。
36. 作为用户，我希望默认每十秒查询，异常时退避并遵从明确限流，以便程序能持续而克制地运行。
37. 作为用户，我希望提交前记录待确认状态，以便程序异常退出后仍知道有一次提交尚待核对。
38. 作为用户，我希望页面显示成功后仍按原活动 ID 核对预约，以便不会把无关提示当成成功。
39. 作为用户，我希望超时或断线后先核对原提交，以便不会盲目再次提交。
40. 作为用户，我希望结果持续不明时暂停其他提交并通知，以便不在未知状态下继续增加预约。
41. 作为用户，我希望本机重启后保留待确认、冷却和退避，以便停止和恢复不会绕过保护。
42. 作为用户，我希望不设置邮件也能运行，并能查看终端和本地事件，以便通知渠道不是启动前提。
43. 作为 Gmail 用户，我希望只配置完整邮箱和应用专用密码即可启用通知，以便减少配置步骤。
44. 作为其他邮箱用户，我希望保留显式 SMTP 主机、端口和收发地址配置，以便沿用现有 TLS 邮件服务。
45. 作为用户，我希望成功单场、目标完成、人工认证、待确认结果和持续失败时获得事件通知，以便知道何时需要关注。
46. 作为用户，我希望正常轮询保持安静、同一故障不重复提醒，以便通知不会形成噪声。
47. 作为用户，我希望发信失败不改变预约结果或触发重复预约，以便邮件故障不会扩大为业务错误。
48. 作为用户，我希望认证实际需要人工介入时保留任务并安全退出，以便不反复触发登录或短信。
49. 作为用户，我希望不必配置短信输入或远程桌面，以便服务器运行不增加这些交互流程。
50. 作为用户，我希望先进行不提交、不发邮件的只读检查，以便区分环境、登录和数据问题。
51. 作为用户，我希望单独测试邮件和查看本地运行状态，以便无需为诊断启动新的预约。
52. 作为用户，我希望状态输出区分任务状态、进程是否运行及最近查询结果，以便不把遗留状态当作程序健康。
53. 作为用户，我希望程序只使用校验证书的 HTTPS 传输认证和业务数据，以便凭据与票据不通过明文发送。
54. 作为用户，我希望配置、日志和邮件不泄露凭据、会话和个人活动记录，以便可以安全排查问题。
55. 作为维护者，我希望复用已有应用边界和离线浏览器测试，以便验证行为而不访问真实学校系统。
56. 作为用户，我希望文档明确哪些能力已经验收、哪些尚待验证，以便不把离线测试或一次登录成功当作长期预约可靠性的证明。

## Implementation Decisions

- 仅调整浏览器项目。复用现有 uv、Python、Playwright 同步 API 和已安装依赖；按用户后续确认，统一使用 Playwright 管理的 Chromium，安装阶段显式下载，不再依赖系统 Chrome 或 Windows App Paths。领域规则、任务恢复及邮件逻辑可复用已有成果，但不要求另一个仓库在运行时存在。
- 命令行增加 `--headless`。普通启动在所有平台默认有头，参数存在时无头；不以操作系统或旧的模式环境变量静默改变这个约定。共享浏览器启动能力的辅助入口遵循同一模式语义，不扩展其采集功能。
- 学校交互由页面导航、控件填写和点击触发。允许只读已经绑定到页面的数据以取得活动 ID、打卡、违约和取消状态；不由自动化脚本另建 HTTP 客户端、使用 Playwright 请求上下文、注入 fetch／XHR 或直接调用页面业务方法替代交互。网页自身正常发出的请求属于页面运行。
- 活动 ID 是身份依据。未知结构、无法唯一定位、查询错误、矛盾记录或缺少必要状态时暂停新增，不退回标题猜测，不把加载失败当空列表。校验完整列表、全部筛选、加载完成及已提供的总量证据；不能把未读通知数当历史总数。
- 普通业务启动先建立认证并读取学校记录，重建已选听、待参加计划和缺口；不能只根据本地历史完成标记跳过网站核对。明确的本地状态查询入口除外，且其输出不能冒充最新学校结果。本地检查点是本机安全恢复辅助，不是个人预约状态的权威来源，也不是在新机器启动的前置条件。
- 固定八场及法律、艺术、心理健康各至少一场，不新增年级、学生类别、三场目标或截止日期。四类系列讲座为心理健康、法律、艺术、其他；沙龙不计入也不自动预约。已有状态未知、类别未知、同 ID 矛盾或已提供总数不一致时暂停新增。
- 标题列表非空时完整匹配且仍受所有筛选约束；默认允许线上、线下仅允许明确配置校区。业务数据来源和映射须由真实页面证据支撑，线上／线下识别不以未经验证的字段假设放行。
- 冲突覆盖全部有效预约，首尾相接视为冲突。已有重叠记录逐次优先已打卡、补当前缺少类别、结束较早、活动 ID 固定顺序，选择互不冲突的本地计数场次；更新缺口后再选择，不承诺全局最多场次，不取消或改写学校记录。
- 候选先补缺少的必需类别，其余按配置类别顺序、线上优先、开始较早排序。验证码初次识别后最多重新取图三次，仍失败则该场冷却五分钟；明确已满或不可预约可跳过。超时或未知响应不能按验证码错误处理。正常查询默认十秒，失败指数退避并遵从学校明确限流。
- 每次真实提交前持久化活动 ID 和待确认状态，之后按学校记录确认。结果持续不明时只核对、暂停其他提交并通知；本机恢复保留待确认、冷却和退避，不用删除或重建任务绕过保护。
- 同一账号只运行一个预约实例是使用约束，包括两个项目及不同机器之间。本机任务锁用于防止同一任务重复运行；不新增跨主机锁、自动状态同步或手动迁移要求，不承诺跨主机提交的全局去重。
- 通知复用可选邮件方案：全部字段缺省／为空时关闭，单独保留默认端口不启用；尝试配置但缺项或无效时明确报错。Gmail 支持邮箱与应用专用密码自动补齐 TLS 主机及自己收信，显式 SMTP 设置优先，其他服务保留既有 TLS 配置。
- 单场成功后通知并继续；计划覆盖等待核对，实际目标达标后通知并结束。连续三轮查询或处理失败提醒一次，恢复后重置；人工认证、提交待确认和可捕获异常退出按规则通知。发信失败只记录，不重发、不改变业务结果。SMTP 接受不代表收件箱送达，强制终止或断电不保证通知。
- 后续确认的邮件简化与汇报规则见[邮件通知需求](notification-requirements.md)：每位用户可选配置自己的发件邮箱，默认发给自己，运行期间每天北京时间 20:00 汇报；不增加统一发信后台。
- 不提供短信发送、短信输入或远程桌面。会话失效可先重新登录；认证无法完成、明确凭据拒绝或账号受限时停止自动尝试，保存任务、记录事件并按邮件配置通知后退出，不能继续受保护业务或绕过认证。
- 配置继续统一管理，保留进程环境变量优先和已有用户配置。除已明确由命令行决定的浏览器模式外，同步相关配置样例、双语说明和排错文档。凭据、票据及完整个人记录不进入仓库、公开日志或邮件；诊断脱敏。
- 认证与业务实际传输使用校验证书的 HTTPS，保留必要的原始服务标识。沿用已有首次登录网络回退边界，不把证书或认证错误当 DNS 错误；运行中不自动切换网关或重放预约。环境安装、依赖新增及真实外部操作按各自授权处理。
- 保留只读检查、状态查询、独立测试邮件和已完成目标重新核对入口的适用行为。只读检查不提交预约、不发邮件、不创建或重置任务；状态查询不启动浏览器。已有重新核对入口不得变成普通启动先看网站的替代条件，也不能重置活跃或待确认任务。

## Testing Decisions

- 用户已确认：应用运行入口作为主要测试边界，替换学校页面访问、时间、休眠、OCR、邮件和临时状态；用命令行边界验证参数，用本地构造页面验证真实浏览器操作。优先沿用已有边界，不为了规格新增分散的测试专用接口。
- 好的测试断言外部行为：启动的是哪种模式、最终选中哪个活动 ID、是否提交、何时等待／退出、学校结果如何影响目标、本地恢复是否阻止重提、通知和安全输出是否正确。避免只断言内部方法调用顺序、当前选择器字符串或复制实现分支。
- 模式测试覆盖任意受支持系统不加参数均有头、添加参数均无头；旧模式环境变量或平台判断不能覆盖命令语义；同时覆盖共享浏览器入口及清理、中断、异常路径。
- 应用测试覆盖八场及三类目标、计划占位与等待、取消／违约后补足、已结束待确认、缺少类别预留、超过八场仅补必需类别、沙龙排除、所有筛选共同生效和全部有效预约冲突。
- 数据测试覆盖稳定 ID、同名不同场、重复与矛盾记录、未知类别／状态、时间解析失败、首尾相接、链式重叠、优先级动态更新及未计数预约仍阻止冲突。列表加载错误、过滤不全、数量证据矛盾不能被当作空历史。
- 浏览器测试使用 Playwright 管理的 Chromium 加受控页面和拦截外部请求，验证导航、全部筛选、按 ID 重定位、页面重排、验证码填写、精确预约按钮及结果确认，确保不会误点取消。所有数据均为构造样本，不能读取真实配置或联系学校。
- 恢复测试覆盖提交前持久化、点击后超时、迟到成功、未知结果下禁止其他提交、本机重启保留保护、明确验证码错误的有界重试与冷却、候选轮换和限流等待；网站数据仍是结果判断依据。
- 普通启动在无本地状态、存在本地状态或本地曾记录完成时，都应先通过学校记录核对进度。不得要求迁移其他机器的状态目录，也不测试或承诺跨主机分布式一致性。
- 通知测试使用替代邮件服务，覆盖关闭、Gmail 补齐、显式配置优先、无效配置阻止启动、三次失败提醒和恢复重置、认证受阻退出、待确认通知、发信失败不重提、日志和邮件不泄露敏感内容。
- 复用既有配置隔离、导入无副作用、浏览器生命周期、网络回退、应用流程、任务锁和邮件回归作为先例；重新审查提前生成草稿中的测试，尤其修正仍把平台自动选择当正确行为的断言。
- 离线通过后分别验收 Windows 有头和 Linux 无头，模式切换也可在受支持环境验证。真实登录、非空候选映射、完整历史、真实预约、实际 OCR、会话失效及至少二十四小时观察分别记录结果；真实预约、发信或部署须另行授权，未遇到的场景保持待验证。

## Out of Scope

- 修改、合并、迁移、部署或依赖独立的 HTTPS 项目。
- 按操作系统自动选择模式，以及用额外模式配置静默覆盖命令行默认值。
- 浏览器只负责登录、随后用接口客户端执行业务的混合方案；运行时由 AI 自动改代码修复网站变化。
- 短信发送／输入、远程桌面、绕过学校认证或保证永远不需要人工认证。
- 跨机器接续、自动同步、必须手动搬迁状态目录、跨项目共享本地状态、跨主机分布式锁及多账号并发。
- 自动取消预约、修改学校打卡或违约记录、承诺学院最终考核认定。
- 新增年级、三场目标、考核截止日期、个人日历、日期范围、每日可用时段或讲座时长筛选。
- 新增主动通知渠道、邮件失败自动重发、守护服务、服务器重启自动拉起和自动修改系统环境。
- 本次规格整理过程中继续修改实现、运行真实预约或测试邮件、部署、提交、推送或回退此前暂存代码。
