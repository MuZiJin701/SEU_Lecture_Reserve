# 浏览器版首次登录网络故障回退与安全诊断

日期：2026-10-16。状态：已实现并通过离线验收；真实学校登录与预约未验证。下文保留已确认规格，实施结果见末尾记录。

已发布：[GitHub Issue #1](https://github.com/MuZiJin701/SEU_Lecture_Reserve/issues/1)，标签为 `ready-for-agent`。

## Problem Statement

用户通过讲座预约程序进入学校系统时，即使 Clash 的 TUN 模式此前正常，也可能突然无法访问学校 VPN。浏览器显示连接被关闭，但真正的故障可能是 Clash 内部未能解析学校 VPN 的真实地址。当前登录失败信息容易让用户检查凭据或延长短信等待时间，不能帮助用户辨别网络问题。

本次故障中，Clash 日志显示学校 VPN 走直连但真实地址解析失败；使用已核实的真实地址进行独立 HTTPS 请求可正常收到跳转。重新联网并重启 Clash 后访问恢复，具体上游 DNS、缓存或内核触发原因未确定。连接关闭本身不是 DNS 失败的充分证据。

用户希望保留现有浏览器操作方式、登录、筛选和预约流程，在可控范围内尝试手动配置的备用地址，并得到不泄露认证资料的网络诊断，无需修改系统 DNS 或 Clash。

## Solution

增加可选的 SEU_VPN_IP 配置。程序首次启动仍使用正常域名解析；仅当首次登录失败，且本次登录过程中学校 VPN 主框架导航出现指定网络错误时，才关闭原浏览器，使用备用地址重启一次，并从讲座入口重新登录。

备用地址只覆盖 vpn.seu.edu.cn，继续以学校域名访问并验证 HTTPS 证书。用户可能需要再次完成短信认证，不承诺保存原登录状态。没有配置备用地址、错误不符合条件或备用尝试仍失败时，安全地报告结果并退出登录流程。

预约主程序和验证码采集入口使用相同规则。首次登录完成后的工作阶段只增强网络诊断，不新增自动切换地址、重启浏览器或重放预约。

## User Stories

1. 作为讲座预约程序用户，我希望继续使用现有的可见 Chrome 操作方式，以便保持熟悉的登录与预约体验。
2. 作为网络正常的用户，我希望程序优先使用正常 DNS，以便不受额外地址覆盖影响。
3. 作为不需要备用地址的用户，我希望可以不填写 SEU_VPN_IP，以便沿用原有网络行为。
4. 作为偶遇学校 VPN 解析故障的用户，我希望手动配置一个备用 IP，以便在正常访问失败后尝试恢复登录。
5. 作为配置使用者，我希望能填写单个 IPv4 或 IPv6 地址，以便使用已核实的学校 VPN 地址。
6. 作为配置使用者，我希望无效地址在浏览器启动前报错，以便及时修正配置。
7. 作为配置使用者，我希望进程环境变量仍优先于项目环境文件，以便沿用项目已有配置习惯。
8. 作为登录失败的用户，我希望只在学校 VPN 出现已约定的网络错误时回退，以便不把所有登录问题都误当作解析问题。
9. 作为遇到连接关闭或重置的用户，我希望也能获得一次备用地址尝试，以便覆盖类似本次 Clash 内部解析失败的表现。
10. 作为已经登录成功的用户，我希望早前无关或已恢复的请求失败不触发重启，以便不中断正常使用。
11. 作为登录中的用户，我希望图片、统计脚本等子资源失败不会触发回退，以便避免无关故障打断认证。
12. 作为其他学校域名访问失败的用户，我希望程序说明实际故障域名，以便不误用仅适用于学校 VPN 的备用地址。
13. 作为密码或短信认证失败的用户，我希望程序不尝试切换 IP，以便认证问题得到正确处理。
14. 作为遇到证书错误的用户，我希望程序保留证书校验，以便不通过降低 HTTPS 保护来完成登录。
15. 作为需要回退的用户，我希望原浏览器先关闭、再启动备用浏览器，以便不残留多个登录窗口。
16. 作为需要回退的用户，我希望程序清楚提示会重新登录且可能再次要求短信认证，以便理解重启带来的影响。
17. 作为备用地址也不可用的用户，我希望程序只尝试一次后退出，以便避免无限重启或地址切换。
18. 作为使用 Clash 的用户，我希望程序不修改系统 DNS、Clash 配置或其他网站的路由，以便限制改动影响。
19. 作为验证码样本采集用户，我希望采集入口与预约入口具有相同的登录恢复能力，以便不分别配置两套网络行为。
20. 作为正在扫描讲座的用户，我希望收到安全的网络错误提示，以便区分网络异常和正常没有候选讲座。
21. 作为正在提交预约的用户，我希望这项功能不自动重启或重放预约，以便不因网络恢复引入重复提交风险。
22. 作为提供诊断信息的用户，我希望日志只包含故障域名和安全错误类型，以便不暴露账号、票据、Cookie 或完整跳转链接。
23. 作为维护者，我希望配置样例与中英文说明同步更新，以便用户准确理解启用方式和限制。
24. 作为维护者，我希望通过离线回归检查验证配置、回退条件、尝试上限和资源清理，以便无需访问真实学校系统即可验收本次修改。

## Implementation Decisions

- 保留现有 Playwright 同步 API、可见 Chrome、筛选排序、人工短信认证及预约成功一场后退出的行为；不迁移到纯 HTTP，不新增依赖。
- 修改共享配置加载和校验模块、共享浏览器启动与登录模块以及预约和验证码采集两个入口。复用已有调用关系，首次登录回退在共享流程中实现，避免两个入口各维护一套逻辑；不预先约束新的公共函数名称。
- SEU_VPN_IP 未配置时默认空，清理首尾空白后为空即禁用回退。按用户后续要求，配置样例预填 2026-10-16 核实的 `121.249.14.2`；运行代码不内置地址。非空只接受单个 IPv4 或 IPv6 字面地址，拒绝域名、URL、携带端口及无效值，错误仅说明配置项和要求，不回显原输入。沿用环境变量优先于项目环境文件的规则。
- 首次浏览器启动不覆盖解析，不提前探测学校服务，不自动查询或猜测备用地址。
- 监听首次登录期间的主框架导航请求失败，只为准确主机名 vpn.seu.edu.cn 记录回退资格；不使用域名后缀匹配，不因子框架、子资源或其他域名失败而取得回退资格。
- 回退错误集合严格限定为 ERR_NAME_NOT_RESOLVED、ERR_CONNECTION_CLOSED、ERR_CONNECTION_RESET；必须该次首次登录最终失败、已观察到合格失败且配置了备用 IP，才允许回退。首次登录成功时即使曾出现可恢复的失败，也不重启。
- 证书错误、凭据错误、短信认证失败以及没有合格网络失败证据的普通等待超时不触发回退。网络提示陈述实际错误，不声称连接关闭或重置已经证明 DNS 故障。
- 回退顺序是关闭原浏览器、以单域名解析覆盖启动备用浏览器、从讲座入口重新登录。每次程序启动最多一次备用尝试；回退标记不能被后续刷新或重新登录重置。
- 使用 Chrome 启动时的 host-resolver-rules 单独映射学校 VPN，IPv6 使用该规则要求的正确格式；URL、Host、TLS SNI 及学校域名证书校验保持不变。不得启用忽略证书错误，不把 HTTPS 入口改成裸 IP 地址。
- 不保存或迁移原浏览器的登录状态，不承诺免除再次短信认证。登录成功之前不得启动讲座扫描或验证码采集工作。
- 未配置备用地址时登录失败即退出；首次登录遇到不符合回退条件的错误时退出；备用登录失败也退出。启动、页面创建、登录失败和中断路径均负责清理已创建的浏览器资源。
- 首次登录成功后停止收集回退资格；后续扫描、预约、验证码采集和现有重新登录路径不得触发本功能的备用浏览器重启。
- 工作阶段增加网络诊断，但不新增自动切换 IP 或重放预约，不改变现有预约重试与结果确认策略；该策略的既有限制仍保留，不能将本次修改描述为解决了结果不明的重复提交问题。
- 控制台网络诊断仅允许输出已校验的故障主机名和预定义的安全错误类型；对未知或非预期主机使用固定占位类别，不直接输出不可信 URL 内容。丢弃完整 URL、路径、查询参数及原始 Playwright 异常调用日志，不能输出凭据、Cookie、票据或页面内容。
- 已有登录错误页面和截图继续仅保存在本地，不随 Issue、日志或测试附件上传。配置错误不创建真实浏览器。
- 保留 Chrome 自动发现、Windows App Paths 支持和 --enable-logging 排除；正常结束、异常和中断均清理资源。
- 仅改变本程序对学校 VPN 的解析，不修改系统 DNS 或 Clash，不全局禁用或绕过代理。显式代理若在代理端解析域名，本地覆盖可能不生效，该情况不通过额外代理绕过策略处理。
- 同步配置样例、中英文 README 及中英文使用说明，说明正常 DNS 优先、触发范围、一次重启、可能再次短信、工作阶段不回退和备用地址可能过期等限制。
- 不新增数据库、远程服务、自动 IP 发现、配置开关集合或通用网络恢复框架；本次没有需要扩充的讲座领域术语或单独 ADR。

## Testing Decisions

- 测试边界沿用用户已确认的离线范围：优先在两个入口共同经过的浏览器启动／首次登录协调边界验证外部行为；配置加载使用已有隔离环境测试。无需引入通用恢复框架或专供测试的新公共接口。
- 主要断言用户可观察的结果：首次正常登录不回退、只有合格失败才增加一次登录尝试、旧窗口关闭、备用失败退出、工作只在成功后开始。避免绑定内部函数拆分、私有状态结构或无业务含义的调用顺序。
- 复用已有配置测试的临时环境文件与干净环境变量方案，覆盖未设置、空值、首尾空白、合法 IPv4／IPv6、非法值不回显、环境优先级、VPN 样例地址及其他样例配置与默认值一致性；不得读取真实项目环境文件。
- 复用现有浏览器启动／登录测试的模拟页面、可控异常和资源清理检查，以表驱动方式覆盖三个合格网络错误；验证最多一次回退、两个入口一致、正常登录成功不回退，以及备用启动或页面创建失败时的清理。
- 通过可控请求失败事件检查准确域名和主框架限定；排除其他域名、名称相似域名、子框架、子资源、证书错误、普通超时和无对应网络证据的认证失败。
- 覆盖阶段隔离：首次登录成功后出现故障、工作阶段再次调用现有登录流程，均不得重新获得备用地址回退资格；不得因本次功能额外触发预约提交。
- 在事件和异常中注入模拟密码、票据、Cookie 与带查询参数的 URL，检查输出仅有安全域名和允许的错误类型；原始输入不得进入控制台诊断。
- 复用现有本机 Chrome 内存页面测试习惯，验证正常浏览器行为、资源清理和单域覆盖的行为边界；外部请求全部阻断，仅使用 about:blank 与本机构造页面。无法通过完全离线方式证明真实 TLS 端到端与学校认证成功，不得用模拟检查冒充实测。
- 实现时运行项目规定的完整 unittest 检查，已有预约解析、筛选、确认与 Chrome 发现回归继续通过。文档与配置样例做一致性和链接检查。
- 规格发布本身只校验结构、范围一致性和 Git 差异，不运行会触发学校访问的项目入口；功能测试在实现阶段执行。

## Out of Scope

- 纯 HTTP 迁移、浏览器与 HTTP 混合架构、服务器部署及长期无人值守改造。
- 自动发现“正确 IP”、在运行代码中内置地址、自动更新备用地址或设置多个备用地址。
- 自动修改系统 DNS、Clash、全局代理设置，或为代理端解析增加额外绕过机制。
- 绕过证书验证、密码验证、短信认证或学校网关要求；不自动完成短信认证。
- 首次登录后的自动备用地址切换、无损会话迁移、跨进程登录状态持久化。
- 预约结果不明时的查询恢复、按活动 ID 重构预约确认、重复提交治理，以及筛选和排序行为调整。
- 更改既有扫描频率、重试次数、预约目标数量、统计目标、邮件通知或讲座领域模型。
- 真实学校登录、发送短信、预约、取消或采集真实验证码作为本次自动验收的一部分。

## Further Notes

- 用户已逐项确认保留浏览器版、网络错误集合、两个入口共用、一次重启且重新登录、首次登录阶段限定，并最终确认整体范围；本规格不需要重新采访。
- 采用浏览器重启是启动参数解析覆盖的直接代价；原页面、表单与认证状态不承诺保留。[Playwright 启动参数](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch)、[认证状态边界](https://playwright.dev/python/docs/auth)。
- 网络错误分类来自 Chromium；连接关闭与连接重置分别属于连接错误，不等于域名解析错误。[Chromium 错误定义](https://chromium.googlesource.com/chromium/src/+/HEAD/net/base/net_error_list.h)。
- 单域映射使用 Chromium 现有功能。[映射规则定义](https://chromium.googlesource.com/chromium/src/+/main/net/base/host_mapping_rules.h)。显式 SOCKS 代理可能在代理端解析目标域名。[Chromium SOCKS 说明](https://chromium.googlesource.com/website/+/refs/heads/main/site/developers/design-documents/network-stack/socks-proxy/index.md)。
- [独立 HTTP 版](https://github.com/MuZiJin701/seu-lecture-reserve-http)仅作为问题和配置思路参考；其地址适配器不能直接用于当前 Chrome，也不在此处合并 HTTP 客户端实现。
- 备用地址可能过期，连接或认证故障也可能与 DNS 无关。该功能提供一次有限尝试，不承诺学校服务可用或完整预约成功。
- 依仓库分诊约定，发布到当前浏览器版仓库的 GitHub Issues，并使用 ready-for-agent 标签。
